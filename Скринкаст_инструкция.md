# Пошаговая инструкция для записи скринкаста (5–7 минут)
## Демонстрация работы приложения «Note Service» в Kubernetes (Minikube)

> **Критерий оценки видео**: 4 балла из 4 при выполнении всех шагов:
> 1. Запуск приложения и зависимостей (`kubectl apply...`)
> 2. Вывод всех запущенных подов (`kubectl get...`)
> 3. Масштабирование сервисов до большего числа реплик (`kubectl scale...`)
> 4. Несколько кликов в UI приложения, запущенного в Minikube

---

## 1. Подготовка перед началом записи (за 1 минуту до старта)

1. Откройте окно терминала (настройте читаемый размер шрифта, `Ctrl + Shift + +`).
2. Перейдите в папку проекта:
   ```bash
   cd /home/pavel/projects/sre
   ```
3. Убедитесь, что Minikube запущен:
   ```bash
   minikube status
   ```
4. Если вы ранее уже что-то запускали, очистите кластер, чтобы начать запись на чистом листе:
   ```bash
   kubectl delete -f k8s/
   ```
5. Запустите запись экрана (OBS Studio, SimpleScreenRecorder, Kazam, встроенный захват экрана GNOME/KDE по `Ctrl+Alt+Shift+R`).

---

## 2. Поминутный сценарий видео

### ⏱ Минута 0:00 – 1:00: Введение и запуск манифестов
* **Что делаем в терминале**:
  1. Показываем статус ноды кластера:
     ```bash
     kubectl get nodes
     ```
     *(Показывает, что нода `minikube` в статусе `Ready`)*.
  
  2. Показываем загруженные локальные образы сервисов:
     ```bash
     minikube image ls | grep -E "sre-|postgres"
     ```
     *(Видны образы: `sre-backend:latest`, `sre-migrator:latest`, `sre-frontend:latest`, `postgres:16-alpine`)*.

  3. **Ключевой шаг**: Применяем все манифесты одной командой:
     ```bash
     kubectl apply -f k8s/
     ```
     *(В выводе терминала создаются: `secret/postgres-secret`, `configmap/note-service-config`, `persistentvolumeclaim/postgres-pvc`, `deployment/postgres`, `service/postgres`, `job/note-service-migrator`, `deployment/backend`, `service/backend`, `deployment/frontend`, `service/frontend`)*.

---

### ⏱ Минута 1:00 – 2:30: Проверка подов, джобов и сервисов
* **Что делаем в терминале**:
  1. Смотрим запуск подов:
     ```bash
     kubectl get pods -o wide
     ```
  2. Если поды ещё поднимаются, выполните команду с автообновлением:
     ```bash
     kubectl get pods -w
     ```
     *(Нажмите `Ctrl+C`, когда все поды перейдут в `Running`, а мигратор — в `Completed`)*.

  3. Обращаем внимание преподавателя (голосом или курсором):
     - Под базы данных `postgres-...` в статусе `Running (1/1)`.
     - Одноразовый Job миграций `note-service-migrator-...` перешел в `Completed (0/1)`.
     - Две реплики бэкенда `backend-...` в статусе `Running (1/1)` благодаря проверкам `readinessProbe` на `/healthz`.
     - Две реплики фронтенда `frontend-...` в статусе `Running (1/1)`.

  4. Показываем логи успешно выполненного джоба миграций:
     ```bash
     kubectl logs job/note-service-migrator
     ```
     *(Видно, что применилась миграция схемы `000001_init_schema`)*.

  5. Показываем сервисы и порты:
     ```bash
     kubectl get svc
     ```
     *(Видно: `postgres` на ClusterIP:5432, `backend` на ClusterIP:8080, `frontend` на NodePort:30080)*.

---

### ⏱ Минута 2:30 – 3:45: Масштабирование сервисов (Scaling)
* **Что делаем в терминале**:
  1. Выполняем масштабирование бэкенда с 2 до 4 реплик:
     ```bash
     kubectl scale deployment backend --replicas=4
     ```
  2. Смотрим, как Kubernetes мгновенно разворачивает новые поды:
     ```bash
     kubectl get pods -l app.kubernetes.io/name=backend
     ```
     *(Видим 4 пода бэкенда в статусе `Running`! Поясняем: так как бэкенд stateless по 12 факторам, горизонтальное масштабирование происходит мгновенно без конфликтов)*.

  3. (Опционально) Масштабируем фронтенд до 3 реплик:
     ```bash
     kubectl scale deployment frontend --replicas=3
     kubectl get pods -l app.kubernetes.io/name=frontend
     ```

---

### ⏱ Минута 3:45 – 5:30: Демонстрация работы UI в браузере
* **Что делаем**:
  1. В терминале запускаем команду для открытия веб-интерфейса:
     ```bash
     minikube service frontend
     ```
     *(Команда выведет URL и автоматически откроет вкладку в браузере)*.

  2. **В браузере кликаем по интерфейсу**:
     - Показываем индикатор в шапке: **Postgres Online** (зеленый пульсирующий огонек — значит фронтенд через Kubernetes-сервис успешно общается с бэкендом, а бэкенд — с PostgreSQL!).
     - Показываем маскота **Подсолнуха Санни (Sunny 🌻)**: наводим курсор, маскот подмигивает и шевелит листьями.
     - Создаем категорию:
       - Нажимаем `+` возле «Categories» слева.
       - Вводим название: `Kubernetes / DevOps`.
       - Выбираем золотой/янтарный цвет и жмем «Add».
     - Создаем заметку:
       - Нажимаем «New Note» (или кнопку по центру «Plant your first note»).
       - Заголовок: `Тест в Minikube`.
       - Категория: выбираем `Kubernetes / DevOps`.
       - Текст Markdown:
         ```markdown
         ## Развертывание в Minikube успешно!
         - 4 реплики бэкенда
         - Жидкое стекло (Liquid Glass UI)
         - Маскот Sunny 🌻
         ```
       - Ставим галочку «Pin to top of list» и нажимаем «Create Note».
     - Показываем карточку с эффектом стекла и зеркальными бликами.
     - Нажимаем кнопку переключения темы (Солнце/Луна) — показываем светлую и тёмную темы в стиле Liquid Glass.

---

### ⏱ Минута 5:30 – 6:00: Завершение
1. Возвращаемся в терминал.
2. Делаем итоговый обзор всех компонентов:
   ```bash
   kubectl get all
   ```
3. Говорим заключительную фразу:
   *«Все компоненты микросервисного приложения Note Service успешно развернуты в Minikube, миграции применены через Job, сервисы взаимодействуют через CoreDNS, масштабирование продемонстрировано, UI полностью работоспособен. Спасибо за внимание!»*
4. Останавливаем запись видео.

---

## 3. Шпаргалка всех команд в одном блоке (для быстрого копирования)

```bash
# 1. Проверка ноды и локальных образов
kubectl get nodes
minikube image ls | grep sre

# 2. Применение манифестов
kubectl apply -f k8s/

# 3. Проверка подов и логов мигратора
kubectl get pods -o wide
kubectl logs job/note-service-migrator
kubectl get svc

# 4. Масштабирование
kubectl scale deployment backend --replicas=4
kubectl get pods -l app.kubernetes.io/name=backend

# 5. Открытие UI в браузере
minikube service frontend

# 6. Финальный статус
kubectl get all
```
